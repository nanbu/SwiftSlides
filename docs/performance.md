# 性能の測定

2026-10-03、Swift 6.4の非同期基盤と協調キャンセルを追加した作業ツリーのrelease測定。高速性の比較保証ではありません。
macOS 27.0 arm64 / Apple M2 / Apple Swift 6.4、各操作を別プロセスで5回実行。時間は中央値と最小〜最大、RSSは各プロセスの最大常駐量の中央値と最大値を記録しました。
100枚×10図形、各図形にテキスト・塗り・線を持つ架空資料。画像なし。PPTXは126,324 bytes。

| 操作 | 時間中央値 ms | 時間範囲 ms | 最大RSS中央値 MiB | 最大RSS最大値 MiB |
|---|---:|---:|---:|---:|
| create | 232.50 | 231.43–236.05 | 14.69 | 14.70 |
| read | 210.08 | 206.18–217.19 | 13.50 | 13.53 |
| noop | 206.60 | 205.74–207.13 | 13.56 | 13.56 |
| edit | 437.16 | 422.00–442.02 | 17.55 | 17.58 |
| asyncRead | 218.96 | 209.22–225.07 | 13.58 | 13.69 |
| batch1（12文書・同時1） | 3211.50 | 2546.76–3381.64 | 31.38 | 31.91 |
| batch4（12文書・同時4） | 861.18 | 840.03–916.97 | 38.95 | 39.22 |

createはモデル構築＋エンコード＋ファイル保存。readはファイル読込＋モデル化＋テキスト抽出。
noopはread＋未変更エンコード＋原本bytesとの比較。editはread＋1図形の移動＋strictエンコード＋再読検証。
asyncReadは非同期のURL読込＋モデル化＋テキスト抽出。batch1/batch4は同じURLを12回読み、全結果を保持してテキスト抽出。異なる12ファイルのディスクアクセスを測った値ではありません。

非同期化はUIのActorから処理を移す契約です。単一readの時間短縮を保証しません。今回の一括読取では同時数4の時間が短く、RSSが増えました。入力・OSのキャッシュ・負荷・並行数によって結果は変わります。各ファイルのPackageLimitsと同時数は、プロセス全体のメモリ上限ではありません。

時間はSwift処理区間のwall time。RSSはOSのtimeコマンドが測るプロセス全体の最大常駐量で、モデル単独の割当量ではありません。
キャッシュを強制消去せず、最初に資料を生成した後、表の順で各5回実行。他ライブラリ・他マシン・前の実装との同条件比較は行っていません。

再現スクリプトは`scripts/benchmark.py`。一時的なSwift 6.4 consumerをreleaseビルドして時間・RSS・全サンプルをJSONで出力します。
macOS/Linux用。Swiftとシステムzlib、OSの`/usr/bin/time`を使います。

```sh
python3 scripts/benchmark.py > benchmark.json
```

画像・動画の多い資料、複雑なXML、入力上限付近、Keynote、streamingの速度とメモリは別途測定が必要です。

## E〜Hの選択readerとfile target

2026-10-03、Apple M2 / macOS 27.0 / Apple Swift 6.4のrelease測定。各操作を別プロセスで3回、競合する操作を各roundで交互実行。filesystem cacheを消去せずwarm条件。各枚10個の基本図形と文字、画像なし。PPTXとODPは同じ意味量だがXMLや圧縮率は異なり、形式間の互換性・速度保証には使わない。

時間はURL読込を含む処理区間。readAllは全モデル化＋本文抽出、readOneは索引構築＋中央の1枚のモデル化＋本文抽出。index/oneの個別値は同じreadOneプロセス内の区間。RSSはプロセス全体のpeak。各列は中央値で、最大値は再現スクリプトのJSONに含める。

| 形式 | 枚数 | ZIP bytes | 展開宣言 bytes | 全読取 ms / peak MiB | 索引＋1枚 ms / peak MiB | 索引 ms | 1枚 ms |
|---|---:|---:|---:|---:|---:|---:|---:|
| pptx | 10 | 15,017 | 98,548 | 29.99 / 9.94 | 6.61 / 8.05 | 4.36 | 2.25 |
| odp | 10 | 2,663 | 17,378 | 19.88 / 9.20 | 9.40 / 8.69 | 8.11 | 1.45 |
| pptx | 100 | 114,396 | 908,194 | 246.78 / 13.47 | 19.03 / 8.94 | 16.67 | 2.32 |
| odp | 100 | 5,657 | 128,888 | 183.14 / 15.69 | 53.17 / 12.12 | 51.77 | 1.37 |
| pptx | 1000 | 1,112,953 | 9,017,456 | 2587.20 / 45.75 | 153.77 / 14.34 | 151.07 | 2.42 |
| odp | 1000 | 34,283 | 1,253,888 | 1847.39 / 77.22 | 517.50 / 45.39 | 515.63 | 1.60 |

PPTXは本文を要求した1枚だけ解析する。ODPはcontent.xmlを先に全走査し、page XMLとstyle索引を保持するため、1枚読取でも索引時間とRSSが文書規模に比例する。現在のreaderは圧縮入力をmemoryに持つsnapshotで、file-backed ZIPやcache evictionの実装ではない。

Data sinkは同じPPTX bytesのURL読込・保存・保存後のbytes比較を測定し、エンコードを含めない。Foundation atomicとFileTargetは各roundで交互実行。

| 入力枚数 | bytes | Foundation atomic ms / peak MiB | FileTarget ms / peak MiB |
|---|---:|---:|---:|
| 10 | 15,017 | 1.19 / 5.86 | 0.82 / 5.86 |
| 100 | 114,396 | 1.23 / 6.08 | 1.03 / 6.08 |
| 1000 | 1,112,953 | 1.58 / 7.98 | 4.57 / 7.98 |

1,000枚のsinkはFileTargetの方が遅かった。FileTargetを高速化の保証として提供せず、分割キャンセルと失敗時の原本保持を目的とする。全出力Dataは依然としてmemoryに存在し、StreamingWriterは未提供。

再現: `python3 scripts/benchmark-readers.py`。キャンセルと注入ENOSPCは回帰テストで検査。実容量不足は`python3 scripts/verify-file-target-capacity.py`（macOS、hdiutilと一時volumeを使用）で別に検査した。16MiB HFS+ image、書込前free 262,144 bytes、2,097,152 bytesを保存しENOSPCを確認。元保存先の全bytes一致、一時file回収、volumeのアンマウントを確認。停電・デバイス故障は未検証。
